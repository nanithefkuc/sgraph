# Frozen fixtures

Captured from the extraction source — `mix-dpc` at
`6d7d4ac9fafc70c9eeed67ba8cfe654888d390c8` — by a temporary printing test added
to its `src/rng.rs` and run as:

```sh
cargo test --quiet rng::tests::zz_dump_golden_vectors -- --nocapture
```

The temporary test was removed and that repository restored to a clean tree
immediately afterwards. These are **transcribed outputs of a live run**, not
restatements of `sgraph`'s own code, so they are an independent oracle rather
than a round trip.

Both peers of a code regenerate a check symbol's edge set from its id, so the
PRNG, the sampling algorithm, and the draw order are wire properties. **A change
that moves a value in these files is a format break for every downstream
consumer, not a refactor.** Changing a pinned stream requires a new or versioned
generator; moving a file is not itself a break.

## Files

| File | Contents |
| --- | --- |
| `splitmix64.txt` | `next_u64` streams: `seed` then 8 outputs, all hex. |
| `below.txt` | `below(bound)` streams: `seed bound` then 12 decimal draws. Bounds include 255 and 256 to exercise the Lemire rejection band and its absence. |
| `offsets.txt` | Floyd distinct-k edge sets: `id span k` then `k` decimal offsets, seeded `id ^ 0xA5A5_5A5A_C3C3_3C3C`. Covers `span == k`, `k == 1`, and the clamped `k = min(dc, span)` shapes an early-stream windowed generator hits first. |
| `rfc5053_lt.txt` | RFC 5053 Raptor LT neighbour sets: `K X d a b L` then `min(d, L)` decimal neighbours, where `(d, a, b) = Trip[K, X]`. Corpus: `K` in {4, 16, 100, 1024, 8192} against `X` in `0..64`. |

Lines beginning with `#` are comments. The domain constant appearing in
`offsets.txt` is the one `mix-dpc` used; `sgraph` does not bake in a domain
constant, and it appears only to reproduce the captured stream.
`rfc5053_lt.txt` has a different provenance from the three files above: it was
generated by a separate transcription of RFC 5053 §5.4.2.3 and §5.4.4.1–5.4.4.4,
with the `V0`/`V1` and `J(K)` tables scraped from the RFC text (md5 recorded in
the file header) rather than from any code in this repository. It is therefore a
cross-implementation agreement check on the LT edges themselves, and the
specification — not this crate — is its authority.

## Deliberately not captured here

- **Packet and check-symbol fingerprints.** `sgraph` owns neither packet
  construction nor an encoder loop, so pinning them here would either test
  out-of-scope code or create a second oracle beside
  `mix-dpc/tests/interop.rs`, which already pins them.
- **Residual deficiency scenarios** (`mix-dpc/tests/hdpc.rs:{79,146,228}`). Those
  exercise a dense Cauchy MDS layer and a codec shell, both out of scope, and
  their expected values are a formula over the scenario (`losses − repairs_fed`)
  rather than opaque captured data. Copying them would create exactly the second
  oracle the point above rejects. `sgraph`'s own solver is pinned by
  independently derived cases, and `mix-dpc`'s tests remain the authority for its
  layer — unchanged.
